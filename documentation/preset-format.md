# Формат пресета

Пресет — JSON-файл в `presets/`, читается `analysis/verdict.load_preset()`.
Данные отделены от кода намеренно: правка диапазона не требует
редактирования Python, и можно держать несколько пресетов (разные
профили вкуса/жанра) параллельно, переключая флагом `--preset`.

## Структура файла

```json
{
  "preset_name": "строка, для себя",
  "description": "одна фраза",
  "created": "YYYY-MM-DD",
  "source_doc": "путь к человекочитаемому обоснованию, опционально",
  "zones": [ ... ],
  "axis_reliability_ceiling": { "имя оси": число }
}
```

`axis_reliability_ceiling` — необязательный информационный блок
(см. `methodology.md`, раздел про потолок надёжности); движком не
используется напрямую, справочно для человека, читающего пресет.

## Запись `zones[i]`

| поле | тип | обязательно | смысл |
|---|---|---|---|
| `metric` | строка | да | имя метрики, как в выходе `analysis/engine.py` (напр. `spectral_slope`, `band_frac_low`) |
| `source` | строка | да | `mix` \| `vocals` \| `bass` \| `drums` \| `other` |
| `granularity` | строка | да | `track_avg` \| `window` \| `section` — справочно, движком не проверяется строго. `section` (ТЗ-05 Б9) — уровень между окном 4с и целым треком, напр. драматургическая арка (`analysis/sections.py`) |
| `axis` | строка | да | человекочитаемое имя оси/вопроса, для отчёта |
| `liked_lo`, `liked_hi` | число или `null` | ключ обязателен, значение может быть `null` | диапазон значений, статистически связанный с положительной оценкой; `null` у обеих — зона `direction_only` или `no_zone`, диапазона нет вообще |
| `disliked_lo`, `disliked_hi` | число или `null` | нет | диапазон для противоположного полюса — не обязателен, но без него статус "на границе, ближе к X" не определяется (не с чем сравнивать расстояние) |
| `reliability` | строка | нет (default `medium`) | `high` \| `medium` \| `low` \| `pending` \| `no_zone` — см. ниже |
| `direction_only` | bool | нет (default `false`) | `true` — есть только направление ("чем выше тем лучше"), не числовой диапазон |
| `higher_is_liked` | bool | нет (default `true`) | используется только если `direction_only=true` |
| `evidence_type` | строка | нет (default `""`) | `between_songs` \| `within_song` \| `within_mix_versions` — КАК получена корреляция, обосновывает `reliability` (см. ниже и `methodology.md`) |
| `learned_on` | строка | нет (default `""`) | `mix` \| `demucs` \| `real_stems` — на чём калибровалась зона; `write_report` печатает предупреждение, если реальный запуск использует другой тип источника (напр. зона на Demucs-стемах применена к настоящему трек-ауту) |
| `cluster` | строка | нет (default `""`) | зоны с одинаковым `cluster` измеряют по сути одну ось разными числами (напр. 3 метрики "тонального наклона" микса) — в `write_report` усредняются ВНУТРИ кластера перед суммированием в общий счёт, чтобы не голосовать за одну и ту же ось несколько раз |
| `note` | строка | нет | обоснование, ссылка на конкретную проверку — не для показа, для будущего чтения человеком |

## `reliability` — не декоративная метка

Значение реально взвешивает итоговый счёт в отчёте оркестратора
(`orchestrate.write_report`), а не только подписывает строку в таблице:

| значение | вес в сводном счёте | означает |
|---|---|---|
| `high` | 1.0 | воспроизведено на нескольких независимых источниках/группах |
| `medium` | 0.6 | статистически значимо в одной группе, не перепроверено независимо |
| `low` | 0.25 | слабый/устаревший сигнал, оставлен для истории, не как основа решения |
| `pending` | 0.0 | недостаточно данных, чтобы иметь мнение — не тянет итог ни в какую сторону |
| `no_zone` | 0.0 | **проверено и подтверждено**, что единой зоны не существует — принципиально отличается от `pending`: это не "не хватило данных", это отрицательный результат сам по себе. Используйте, когда метрика измерена, но референсы с одинаково положительной оценкой лежат на разных полюсах этой метрики. |

## `evidence_type` — на чём именно построена корреляция

Три значения, по возрастанию силы вывода:

| значение | что значит | риск |
|---|---|---|
| `between_songs` | сравнение усреднённых по треку значений МЕЖДУ разными песнями (напр. 3 любимых референса) | конфаунд: разницу может объяснять любая другая особенность именно этих треков, не измеряемая ось. Максимум `reliability: low`, обычно `direction_only` (см. `methodology.md`, разбор Шага 11) |
| `within_song` | разные фрагменты/окна ОДНОЙ песни, сопоставленные с оценками | нет межпесенного конфаунда, но n ограничен одной песней — обычно `medium`, `high` не выдаётся без независимой репликации на другой песне |
| `within_mix_versions` | разные сведения ОДНОЙ И ТОЙ ЖЕ песни (напр. 6 профессиональных миксов) | сильнее `within_song` — вариация объясняется решениями сведения, не структурой трека, но всё ещё одна песня |

`reliability: high` в этом пресете не используется вовсе после ТЗ-05 Б1 —
ни одна зона не была независимо реплицирована на нескольких песнях с
контролем на конфаунд. Появление `high` в будущем пресете обязано
означать именно это, не просто "низкий p-value".

## Как построить свой пресет

1. Прогнать `analysis/engine.py` (`track_avg_metrics`/`window_metrics`) на
   корпусе своих треков — получить сырые значения метрик.
2. Собрать перцептивные оценки (см. `methodology.md` — методика опросника
   переиспользуема без изменений: слепые фрагменты, скрытый источник,
   дубли для потолка надёжности, стратификация по экстремумам метрик).
3. Считать корреляции **только внутри одной группы источников**
   (см. `methodology.md` про confound от смешения разных треков) — не по
   объединённому пулу.
4. Для метрик с надёжной внутригрупповой корреляцией — взять диапазон
   значений в верхнем/нижнем терциле (или аналогичном разбиении) по
   положительной оси как `liked_lo/hi`, симметрично для `disliked_lo/hi`.
5. Записать `reliability` честно, ориентируясь на: перепроверено ли на
   независимом источнике (`high`), значимо ли в одной группе (`medium`),
   устарело/заменено ли более точным инструментом (`low`), достаточно ли
   данных вообще, чтобы иметь диапазон (`pending`/`no_zone`).

Готовый пресет кладётся в `presets/<имя>.json`, дальше
`python orchestrate.py --preset <имя>`.
