# Метрики: что считается, чем и почему

Модули — `analysis/metrics/*.py`, каждый содержит `analyze_file(path)` для
целого файла; часть функций (STFT/полосы/психоакустика) — чистые функции
над массивом сэмплов, переиспользуются в `analysis/engine.py` для
скользящего окна. Формат гранулярности у каждой метрики — трек целиком
(`track_avg`), скользящее окно (`window`), либо оба.

## Громкость и динамика — `loudness_dynamics.py`

| метрика | метод | библиотека | гран. |
|---|---|---|---|
| `integrated_lufs` | K-взвешенная интегральная громкость, ITU-R BS.1770 | `pyloudnorm` | track |
| `lra` | Loudness Range, перцентильный разброс short-term громкости (EBU Tech 3342) | своя реализация над `pyloudnorm` | track |
| `true_peak_dbfs` | пик после 4x oversampling (ловит intersample-overs) | своя (scipy resample) | track |
| `sample_peak_dbfs` | пик без oversampling | numpy | track |
| `plr` | peak-to-loudness ratio (true peak − integrated LUFS) | производная | track |
| `crest_factor_db` | пик/RMS по 1/3-октавным полосам, покадрово | своя | track |
| `dr_tt` | блочный dynamic-range (TT-meter style): топ percentile RMS относительно пика по 3с блокам | своя | track |
| `transient_events` | реестр атак/спадов по огибающей | своя | и то, и другое, **не в пресете** |
| `pumping_signature` | автокорреляция огибающей — период накачки компрессора | своя | track, **не в пресете** |

`transient_events`/`pumping_signature` посчитаны и используются как
диагностика в исследовательских скриптах (`legacy_scripts/`), но не вошли
в текущий пресет — не набрали устойчивой статистической связи с оценкой
на обучающей выборке при контроле множественных сравнений.

`plr` и `lra` — величины, по определению требующие всего файла; для
скользящего окна не считаются (см. `documentation/methodology.md`,
раздел про гранулярность).

## Спектр — `spectral.py`

Единая сетка STFT (`n_fft=4096, hop=512`) для всех спектральных метрик.

| метрика | метод | гран. |
|---|---|---|
| `spectral_slope_db_per_oct` | линейная регрессия LTAS (1/3-октавные полосы, 100Гц-10кГц) в log-log | оба |
| `band_frac_{sub,low,lowmid,mud,mid,presence,sibilance,air}` | доля энергии STFT в именованной полосе от суммарной | оба |
| `skewness`, `kurtosis` | моменты распределения энергии по частоте (по кадрам, медиана) | оба |
| `centroid_hz`, `rolloff`, `flatness`, `spectral_flux` | стандартные спектральные дескрипторы | track |
| `n_resonances`, `top_resonance_*` | пик-пикинг на сглаженной LTAS (относительный порог над локальным сглаживанием, не абсолютный) | track |
| `thd_median`, `even_odd_ratio_median` (`harmonics.py`) | THD и отношение чётных/нечётных гармоник **только на устойчивых нотах** (границы нот — из питч-трекинга, см. ниже) | track, только вокал/бас |

Границы именованных полос (Гц): sub 20-60, low 60-120, lowmid 120-250,
mud 250-500, mid 500-2000, presence 2000-5000, sibilance 5000-8000,
air 8000-16000.

На ML-разделённых источниках (см. `methodology.md`) сигнал НЧ-фильтруется
на 10кГц перед расчётом — `band_frac_air`/`sibilance` там не считаются
(полоса целиком выше или на границе фильтра, разделение шумит сильнее
всего именно на верхах).

## Психоакустика — `psychoacoustic.py`

| метрика | метод | библиотека | статус в пресете |
|---|---|---|---|
| `warmth_ratio` | энергия 100-500Гц / энергия 1-4кГц | своя (STFT) | низкая надёжность (см. ниже) |
| `harshness` | энергия 2-5кГц, грубое A-взвешивание, /RMS | своя (STFT) | низкая надёжность, оставлена для истории |
| `loudness_sone_*` | громкость по Цвикеру, ISO 532-1 (stationary/time-varying) | `mosqito` | посчитана, не в пресете |
| `sharpness_acum_*` | резкость, DIN 45692 | `mosqito` | `real_sharpness`, гипотеза не подтвердилась ни на одной из двух проверенных выборок — `pending` |
| `roughness_asper` | шероховатость (модуляции 20-300Гц), Daniel & Weber | `mosqito` | `real_roughness`, изначально многообещающий результат не воспроизвёлся на бОльшей выборке — понижена до низкой надёжности (см. ниже) |
| `tonality_tnr_db` | tone-to-noise ratio (ECMA) | `mosqito` | посчитана, не в пресете |

**`warmth_ratio` на уровне целого микса** (энергия 100-500Гц / 1-4кГц,
трек целиком) сравнивалась только между 3 разными треками — межпесенный
конфаунд (см. `methodology.md`): разница между любимыми и нелюбимыми
треками по этой метрике могла бы объясняться любой другой особенностью
именно тех 3 треков, не обязательно тёплым звучанием. Понижена до низкой
надёжности, числовой диапазон снят, оставлено только направление.

**История и текущий статус `harshness`/`real_roughness`.** `harshness` —
самодельная эвристика (грубая имитация "резкости" через энергию в полосе
2-5кГц), введённая до того, как дошли руки посчитать настоящий
психоакустический sharpness/roughness через `mosqito` (дорогая по CPU
операция, roughness — самая медленная метрика во всём наборе, порядка
10 минут на трек длиной несколько минут). На маленькой внутренней проверке
(одна группа треков, n≈9-10, контроль межпесенного confound'а) `harshness`
показала *верное направление* по оси тепло/холодно, но `roughness_asper` —
противоположное по знаку тому, что интуитивно ожидалось: не меньше
шероховатости = теплее, а БОЛЬШЕ шероховатости = теплее. Физически
осмысленно (аналоговая/ламповая теплота на слух часто и есть лёгкие
гармонические искажения, не их отсутствие) и было независимо подтверждено
на слух на out-of-sample треке.

**Дальнейшая проверка на бОльшей выборке эффект не подтвердила.** После
дозаполнения корпуса (та же метрика, посчитанная на всех доступных
версиях сведения одного трека, n=18 против исходных n=9) корреляция
`roughness_asper`↔тепло/холодно упала практически до нуля (см.
`preset-provenance.md` — полный разбор чисел). Даже при повторной проверке
внутри исходной маленькой группы, после честного контроля на
статистическую независимость соседних измерений, значимость держится не
на той оси, что заявлена как основная. Итог: `real_roughness` понижена до
низкой надёжности, числовой диапазон снят — остаётся только направление,
частично поддержанное качественным (не статистическим) прослушиванием.
Это не отменяет физическое объяснение (оно остаётся правдоподобным), но
именно ЭТА конкретная статистическая находка оказалась хрупкой — учебный
пример того, зачем вообще нужна проверка на независимой/бОльшей выборке,
а не остановка на первом значимом p-value. `harshness` при этом
по-прежнему оставлена с низким (не нулевым) весом, а не занулена и не
удалена — направление у неё не противоречит `real_roughness`, просто
инструмент грубее.

## Пространство — `stereo_space.py`

Стерео-корреляция, M/S-соотношение (эквивалент ширины), баланс L/R,
годограф (correlation/axis ratio), потеря при сведении в моно по полосам.
Только на целом миксе — у ML-разделённых источников нет самостоятельной
стереокартины, которую было бы осмысленно интерпретировать отдельно от
контекста микса.

**Известный отрицательный результат:** ширина стерео (`overall_ms_ratio`)
не показала единой зоны "нравится" — два независимых сильно позитивно
оцененных референсных трека находятся на противоположных полюсах шкалы
ширины (один почти моно, другой заметно шире среднего). Оставлена в
пресете со статусом `no_zone`, не удалена — это подтверждённый факт "эта
метрика тут не предиктор", а не незакрытый вопрос.

## Реверберация — `reverb.py`

Метод: находим изолированные онсеты (пауза без нового события ≥300мс до
и после), берём "хвост" после онсета, интегрируем обратным
методом Шрёдера (energy decay curve), линейно фитим наклон EDC в заданном
диапазоне дБ (по умолчанию −5…−25дБ) и экстраполируем до −60дБ → RT60/EDT.
Дополнительно: DRR (энергия первых 50мс к последующей), C50/C80 (индексы
чёткости из акустики залов), спектральный наклон хвоста, оценка предзадержки.

## Вокал: питч — `pitch_vocal.py`

- **F0**: pYIN (`librosa.pyin`), с voiced-флагом и confidence.
- **Сегментация нот**: переход = участок, где производная F0 по РЕАЛЬНОМУ
  окну ~100мс (не по одному кадру) превышает 50 центов — иначе вибрато
  (типично 3-8Гц) само по себе рассыпает устойчивую ноту на десяток ложных
  "переходов", потому что покадровая производная у вибрато скачет сильно
  и часто, а за окно ~100мс колебание туда-обратно себя гасит.
- **Интонация**: отклонение медианного питча ноты от ближайшего
  полутона равномерной темперации, в центах.
- **Вибрато**: FFT остатка (центы минус медиана ноты) на устойчивой ноте,
  пик в полосе 3-10Гц → частота, RMS остатка × √2 → глубина.
- **Признаки тюна**: аномально плоские участки (дисперсия <5 центов дольше
  200мс) и резкие скачки (>80 центов быстрее 30мс).
  ⚠️ На ML-разделённом вокале этот детектор ненадёжен — артефакты
  разделения дают физически невозможную частоту "скачков" (тысячи в
  минуту); годится только на честно изолированных дорожках записи.

## Вокал: текстура — `vocal_texture.py`

- **Форманты (LPC)**: кадр 44.1кГц ДЕЦИМИРУЕТСЯ до 10кГц перед LPC
  (порядок 12). Без децимации LPC на полной полосе тратит бюджет полюсов
  на моделирование гармоник/шума до 22кГц, и вместо трёх формант в районе
  700/1200/2600Гц находится 1-2 смазанных широкополосных корня — стандартный
  приём (тот же, что в Praat и подобных трекерах): сначала снизить частоту
  дискретизации примерно до удвоенной верхней границы интересующей полосы.
- **Дыхания**: безголосые кадры, высокая энергия 2-8кГц, высокая spectral
  flatness именно В ЭТОЙ полосе (не по всему спектру — иначе flatness
  ложно проваливается к нулю за пределами полосы).
- **Сибилянты**: безголосые кадры, локальный пик энергии 5-10кГц над
  скользящим медианным фоном (относительный порог).
- **Отношение согласные/гласные**: по энергии voiced/unvoiced кадров.

## Гармония и ключ — `harmony_key.py`, `harmony_dissonance.py`

Chroma-based определение тональности и аккордов, кривая диссонанса
(модели Sethares/Vassilakis по частотно-амплитудным парам парциалов),
расстройка вокал-бас (медианное отклонение по одновременно звучащим
устойчивым нотам двух источников, с фильтром кадров-кандидатов на
унисон/октаву — иначе обычная гармония вроде терции/квинты ложно
засчитывается как расстройка). Код рабочий и покрыт тестами на синтетике
(`tests/synthetic/test_harmony_key.py`), лежит в `analysis/metrics/` как
и остальные core-модули — но НЕ подключён к `engine.py`/пресету: не было
системно провалидировано на обучающей выборке в текущем цикле
исследования. Используется из `legacy_scripts/` в исследовательских
раннерах, физически не там.

## Многослойность и маскирование — `layering.py`, `masking_erb.py`

**Сознательно не входят в дефолтный прогон оркестратора.** Это
попарный анализ РЕАЛЬНО одновременно записанных дублирующих дорожек:
одновременность звучания, расхождение по высоте/времени, риск фазовой
гребёнки (`layering.py`), и психоакустическое маскирование одной дорожки
другой по ERB-полосам (`masking_erb.py`). Оба требуют дорожек,
записанных как физически раздельные источники одного и того же
исполнения — у ML-разделения (Demucs) такого разделения на "дубль 1 vs
дубль 2" нет в принципе, там один смешанный `vocals`-стем на весь трек.
Код рабочий, лежит в `analysis/metrics/` как и остальные core-модули
(`masking_erb.analyze_group` покрыт регрессионным тестом на синтетике,
`tests/synthetic/test_block_v_regressions.py`), но не обобщён под
произвольный вход и не подключён к `engine.py`/пресету. Используется из
`legacy_scripts/` в исследовательских раннерах, физически не там.

## Шум — `noise.py`

Обнаружение гула/наводок и оценка SNR по тихим участкам трека (не по
всему файлу целиком — гейт по энергии, иначе громкие участки размывают
статистику шумового пола).

## Секции и драматургическая арка — `sections.py`

Третий уровень гранулярности, между окном (4с) и целым треком — только на
миксе. Мотивация: усреднение по окнам и по всему треку одинаково слепо к
МАКРО-профилю громкости (тихое начало → громкая кульминация) — это
характеристика видна только на уровне отдельных музыкальных секций
(куплет/припев/бридж и т.п.), не на распределении коротких окон.

Границы секций: если для трека есть ручная разметка
(`_analysis/sections.csv`, ведётся отдельно, не автоматически) — используется
она; иначе — автоматическая сегментация по self-similarity матрице
(MFCC+chroma) с новелти-кривой Foote (2000), работает на произвольном
входе без разметки.

На каждую секцию считается integrated LUFS (pyloudnorm, не приближение
через RMS) и уровень относительно среднего по треку — так секции
сравнимы между версиями с разной абсолютной громкостью мастеринга.
Секции короче 0.5с исключаются (слишком мало для гейтированного LUFS).

`arc_db` = средний уровень 2 самых громких секций минус средний уровень 2
самых РАННИХ по времени секций (не самых тихих — важно именно "как трек
открывается против того, куда он приходит", а не любая тихая секция где
угодно в треке). Дополнительно считаются `section_spread_db` (std по
секциям) и `section_range_db` (max−min) — сам факт наличия макро-динамики,
не только направление.
